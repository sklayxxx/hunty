# Hunty / iced — экспериментальный клиент

Это начало переноса, а не замена Hunty 0.7.0. Рядом остаётся прежний клиент на Tauri/в браузере. Прототип использует то же P2P-ядро и протокол, но интерфейс и медиастек ещё не перенесены целиком.

В прототипе: регистрация тестового профиля, список комнат, добавление друзей по коду и приём заявок, создание групп и добавление друзей в них, «Избранное», чтение и отправка текста, ответы, реакции, правки и удаление сообщений. Список и история обновляются опросом раз в 3 секунды. Звонки, видеосвязь, демонстрация экрана, запись и просмотр клипов, вложения, настройки и многие остальные функции старого клиента в iced **ещё не реализованы**. Для общения можно добавить друга по коду или создать группу.

```sh
cargo run -p hunty-iced
```

Для безопасности прототип по умолчанию хранит отдельный профиль в системном каталоге данных `hunty-iced-preview`. Чтобы проверить копию существующего профиля, скопируй данные в отдельную папку и передай её через `HUNTY_ICED_DATA`. Не запускай два клиента с одной папкой данных; старый Tauri не обязан соблюдать блокировку прототипа. Прежде чем экспериментировать с данными, сделай резервную копию. Windows и macOS пока не проверены.

## Что изменилось в прежнем клиенте

- Локальные HTTP и Tauri-медиаобработчики поддерживают одиночные byte-range-запросы, необходимые для перемотки ранее сохранённых вложений и новых клипов. Клип должен иметь корректный индекс и длительность; неполный или повреждённый файл это не исправит.
- Для демонстрации экрана разрешена адаптация разрешения и fps при перегрузке, а операции над одним WebRTC sender сериализованы. Получение информации о кодеке больше не должно бесконечно задерживать запуск. Это снижает риск зависаний, но само по себе не гарантирует хорошую скорость на любой сети или устройстве.
- Проверки: `node tests/share-sender.mjs`, `node tests/webm-seek.mjs`, `node tests/media-range.mjs` (для обоих нужны ffmpeg и Chromium; последнему также нужен `cargo build -p hunty-node`), `cargo test -p hunty-core media_range`. Для пути к браузеру можно задать `CHROMIUM`.

## Оставшаяся работа

Перенести все окна и действия, сохранить совместимость протокола, добавить нативный захват экрана, устройства аудио/видео, WebRTC, запись/декодирование и перемотку медиа. Для каждой платформы отдельно проверить разрешения, системный выбор экрана, стабильность и производительность с реальными собеседниками. До этого релизы не переключаются на iced.
